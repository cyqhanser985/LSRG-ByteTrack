## 1. 指标口径定义

对每个事件(seq, F, type, tid;switch 另含旧 tracker A),从 track txt 取框,计算:

| 指标 | 定义 | 示例映射 |
|------|------|-------------|
| F_l / gap | F_l = tid 在 **<F 帧**的最后**出现**帧(≠ note 里的"最后 MATCH 帧");gap = F − F_l | 事件帧 100 帧 = F;上次出现 90 帧 = F_l;gap = 10 |
| IoU_last | IoU(tid@F_l, tid@F) | IoU(第 90 帧 ID2 框,第 100 帧 ID2 框) |
| dx_last / dy_last | 中心点位移(带符号):cx(tid@F) − cx(tid@F_l);中心点 = (x+w/2, y+h/2) | x 方向位移、y 方向位移 |
| dist_last | 欧氏距离 √(dx²+dy²) | 欧式距离 |
| IoU_prev / IoU_next | IoU(tid@F−1, tid@F) / IoU(tid@F, tid@F+1)(相邻帧连续性) | — |
| IoU_swap / dist_swap | **仅 switch**:IoU(A@F, tid@F) 与两框中心点距离(事件帧新旧 tracker 空间关系) | — |
| area_ratio | area(tid@F) / area(tid@F_l) | — |

**NA 语义:** tid 在 <F 从未出现(新初始化 tracker 直接接管)→ `no_last_seen`,F_l/gap/IoU_last/dx_last/dy_last/dist_last/area_ratio 全部为空;F−1 或 F+1 无该 tid 框 → `no_prev` / `no_next`;switch 的 A@F 无框 → `no_old`(含 note 中 old_hid 为 unknown 的情况)。na_flag 用 `|` 连接缺失项,字段内不含逗号(口径同步骤 6)。

**口径注意:** note 中的"last frame"(旧目标 A 的最后 MATCH 帧)与本次的 F_l(tracker 最后**出现**帧)是两回事,不混用;本报告全部指标只依赖 track txt 与事件 CSV,不 import motmetrics。

## 5. switch vs reuse 对比解读(核心结论)

**一句话对比:** switch 中只有 61.2% 的事件能算"上一次出现"指标(IoU_last 中位 0.776、位移中位 6.5px、gap 中位 1 但 >5 帧占 19.2%),大量事件是新 ID 直接初始化接管;reuse 则 100% 有历史且 94.2% 是"上一帧还在旧目标上、下一帧顶替到新目标"(IoU_last 中位 0.858、位移中位 4.0px、gap=1 占 94.2%)。**两种情况的关键差异不在"连续性差多少",而在"接管时 tracker 从哪来":switch 常是冷启动/长期丢失后的远距离接管,reuse 几乎总是相邻帧间的紧邻目标顶替。**

具体差异(三数据集合并):

1. **结构差异最大——NA 率:switch 38.8% vs reuse 0%**。switch 中每 3 个事件就有 1 个以上的 tracker 是事件帧才出现的全新 ID(冷启动接管);reuse 按定义不可能没有历史。这是回答"两种情况区别"的第一位事实。

2. **接管距离:switch 的 IoU_last 中位 0.776 低于 reuse 的 0.858,dist_last 中位 6.5px 高于 reuse 的 4.0px**;长尾差距更明显(switch 的 P90 dist_last 44.7px vs reuse 17.8px)。switch 的接管更多发生在"新 tracker 从别处移动到目标上"的场景;reuse 更多是"紧邻目标之间的 ID 传递"。

3. **gap 分布:switch 的 gap 中位 1 但均值 3.7、>5 帧占 19.2%;reuse 的 gap 均值 1.5、>5 帧仅 2.9%**。任务示例"第 90 帧出现、第 100 帧切换"(gap=10)属于 switch 的 >5 类(占 19.2%),是"tracker 丢失约 10 帧后重新出现在目标上并被重新关联"的形态;而最常见形态是 gap=1(上一帧还在画面中)。

4. **相邻帧连续性(IoU_prev/IoU_next)两者几乎相同**(0.74-0.81 附近):事件帧前后 tracker 自身的运动都是连续的,ID 变化是瞬间的"身份切换"而非轨迹断裂——这解释了为什么单个 tracker 看起来正常,但 ID 已经变了。

5. **IoU_swap/dist_swap(仅 switch):事件帧上新旧 tracker 的 IoU 中位 0.383、中心距中位 25px**。旧 tracker 通常在目标附近但未重合(两者在争同一目标区域,一方被匹配算法判为关联、另一方保留),IoU_swap P90 0.61、dist_swap P90 54.6px,存在少量"远距离误接管"(dist_swap 最大 503px,拥挤场景的大跳跃)。

6. **SportsMOT 特殊性**:switch 的 IoU_last 均值仅 0.525(其他数据集 0.65-0.77)、dist_last 均值 33.4px(其他 10-16px)、NA 率 56.3%——快速运动下 tracker 寿命短、重新初始化频繁,ID 切换的"衔接质量"最低,这是运动场景固有困难。

7. **数据集共性**:MOT20(人群)的两种事件 IoU 都最高(switch 0.86/reuse 0.91 中位),因为人群场景目标速度慢、框稳定,切换更多发生在"拥挤导致的遮挡/交叉";MOT17(街景)居中;SportsMOT 最低。

**图规格(与白布口径一致,坐标保真):** 画布纯白 255、尺寸 = 该序列原图 WxH(读首帧取得);图像边界画浅灰矩形(参考系);轨迹 = 事件 tracker 全部帧(第一次出现..最后出现)的框中心折线 + 每帧小圆点,切换前段(帧 < F)用该 ID 黄金角色(dtv.build_id_colors,与视频/白布同色)、切换后段(帧 ≥ F)纯红;线一律粗黑底 + 细彩线(白底可读性);切换点 F 黑色大圈 + 帧号标注(自动放在不与轨迹重叠的空白处);起点/终点黑白双色小方块;总帧数 >500 时圆点降密度(折线保持完整);**switch 例叠加旧 tracker A 全程灰色轨迹**(一眼看出"两 ID 交接");reuse 例不叠加。图内文字纯 ASCII(`{seq} {type} f{frame} {old}->{new}`),中文说明见本报告。

输出:`assets/trajectory/*.png`(本报告包;6 个事件经核验在新事件表中仍存在)。
